# 顶栏与 AI 入口设计规范

> 上位规范：[STANDARD.md](STANDARD.md) 第 5 节「本版专项（v0.4.44dsk 顶栏视觉重做）」。
> 本文不推翻已定的骨架（高度、无缝标签、同色连片、ClearType、Segoe UI），只补三件事：
> **分组语法**、**状态语言**、**AI 入口契约**。
> 改动涉及 `desktop/shell_navbar.py`、`desktop/shell_ai.py`、`desktop/app_window.py`、`desktop/web/panel.*`。

---

## 0. 一句话原则

顶栏只有三段信息：**标签 → 导航 → 地址**。AI 不是第四段，它是「地址」这一段上的一个动作。

任何"再往右放一颗独立按钮"的方案都会破坏这个三段式，也就会重新长出廉价感。

---

## 1. 参考对象：Google 的输入型表面

不是照抄配色，而是抄它四条结构性习惯：

| Google 的做法 | 落地点 | 我们要学的 |
| --- | --- | --- |
| Gemini 入口是**四角星（sparkle）矢量图标**，不是文字，且**常驻在地址栏右端** | Chrome 工具栏右上 / omnibox 内 | 入口用图标、贴着"要问的地方" |
| AI 入口**有键盘通路**（Chrome 是 Alt+G / Search+G） | 侧边栏开合 | 鼠标之外必须有一条键盘路径 |
| 输出走**侧边栏**，与网页并排、不遮内容 | 右侧面板 | 已有的 `set_right_inset` 让位模型，保持不变 |
| 搜索首框有**宽度上限**（584px），不随窗口无限拉伸 | 搜索页 | 胶囊要收窄居中，两侧留对称留白 |
| 所有"输入"表面**只有一个强调色**，其余全是灰阶 | Material | accent 只出现在"当前正在发生的事"上 |

反面参照（就是我们现在的样子）：一颗描边圆环、里面两个字母 `AI`、孤零零挂在最右边 —— 它在读感上是**状态灯**，不是入口。

## 2. 结构规范

### 2.1 三段划分

```
[ 8px ] ← → ⟳ ★ [ 8px ] [ ═══ omnibox ═══ ] [ 8px ]
```

- **左段（导航组）**：back / fwd / reload / star，32px 圆形按钮，`BTN_GAP = 0` 紧贴成组，左起 8px。
- **中段（地址栏胶囊）**：上下内缩 6px（胶囊高 = `nav_h - 12`），左右各留 ≥ 8px gutter。
- **右段（工具簇）**：允许 ≥ 2 个同级图标（star / 未来可能的 ⋮）。
  **禁止**在右段塞单个"孤岛"按钮 —— 一个没有邻居的按钮必须靠描边证明自己是按钮，这正是廉价感的来源。

### 2.2 胶囊内部（从右往左）

```
[ AI chip 28×24 · 圆角 7 ] 4px [ url 文本 ] 6px [ 站点图标 16 ] 9px ‖
```

- chip 右边缘距胶囊右端 **4px**（视觉上与圆角同心，不留"贴边"的局促感）。
- url 文本左对齐，超长省略号；**不居中**（居中会让长短网址在视觉上跳）。
- 站点图标语义不变：空/非 http(s) → 放大镜，https → 锁，其余 → 地球。

### 2.3 空态

地址栏为空 = 它是搜索框。此时**必须**有占位文案（`搜索或输入网址`），
不允许出现"一大条空白胶囊"—— 现在的 `chrome_search.png` 就是一条空胶囊，这是最直接的廉价信号。

### 2.4 几何 token（逻辑像素，乘 `scale`）

| token | 值 | 说明 |
| --- | --- | --- |
| `NAV_H` | 40 | 不变 |
| `MARGIN` | 8 | 段间 gutter |
| `BTN_W` | 32 | 导航按钮方框（圆底直径 = 32-6） |
| `PILL_INSET` | 6 | 胶囊上下内缩 |
| `CHIP_W × CHIP_H` | 28 × 24 | AI chip |
| `CHIP_RADIUS` | 7 | 圆角，非全圆 |
| `OMNI_MAX_W` | 900 | 胶囊最大宽度（窗口足够宽时居中） |

### 2.5 高度不变

本规范**不新增行、不加高顶栏**。任何"再加一条 AI 提示条"的做法都会被否掉：
顶栏的空间预算已经被标签条 38 + 导航栏 40 用完了。

## 3. 样式规范

### 3.1 颜色只从 `ui_bg_scheme` 取

| 用途 | token |
| --- | --- |
| 标签条底 | `bar` |
| 工具栏底 / 激活标签 | `active` |
| 悬停底（任何按钮） | `hover`（= active↔bar 的中点） |
| 主要文字 / 图标 | `fgon` |
| 次要文字、未激活图标 | `fgoff` |
| 分隔线、淡描边 | `sep` |

### 3.2 强调色必须只有一个来源

`install_navbar` 目前把 accent 写死成 `#4C8DFF`，而标签栏、悬浮球、AI 面板用的是
`float_ball_accent`（默认粉 `#FB7299`）。结果是**同一屏两个强调色**，这是最伤"高级感"的细节之一。

- 必须给 `install_navbar` 加 `accent_getter`，与 `install_strip` 同源（`app.sget("float_ball_accent")`）。
- accent 允许出现的位置只有三处：**AI chip 展开态**、**地址栏聚焦描边**、**网页加载进度**。
  其余一律灰阶。悬停态**不用** accent（accent 悬停会显得躁）。

### 3.3 图标

- 16×16 网格、1.5px 描边、`round` 端点、单色。
- **不许用字体符号**当图标（`AI` 两个字母、`✕`、`+` 都属于同一类问题，STANDARD 已经把按钮改成 1px 矢量线）。
- AI 入口用四角 sparkle 路径（凹边贝塞尔），不用圆环、不用星星五角星。
- 图标不随状态改变形状，只改变颜色与底色。

- ★ 自绘字形（放大镜/锁/地球）的布局矩形必须**比字形宽 4px ×2** 并关掉裁剪，
  否则高 DPI 下 GDI+ 会沿矩形左边把墨迹切掉（v0.4.46 就是这么坏的，见 STANDARD 同名补丁）。

### 3.4 层次只靠三件东西

底色三档（`bar` / `active` / 胶囊混色）+ 1px 线 + `alpha=30` 顶部内高光。
**禁止**：阴影、发光、渐变、毛玻璃、彩色描边。GDI+ 上这些一律变脏。

### 3.5 对比度

- 正文与图标 ≥ 4.5:1；dim 文字 ≥ 3:1（现有 `0.82` 混色达标，不要退回 `0.7`）。
- 禁用态用 **0.4 透明度 + 不变形**，不要靠"变细""变灰到看不见"表达。

## 4. AI 入口规范（本文重点）

### 4.1 位置

**收进地址栏胶囊右端**，成为"在这里提问"的一部分。

理由三条：

1. 用户"想问点什么"的地方本来就在地址栏，入口贴着它，心智不用切换；
2. 右边不留孤岛，顶栏回到干净的两段（导航组 + 胶囊），视觉重量下降；
3. 天然获得"输入框旁边"的位置，后续做 `?` 前缀直问、选中文字问 AI 都不用再挪位置。

### 4.2 四态

| 状态 | 底色 | 图标 | 其它 |
| --- | --- | --- | --- |
| 默认 | 透明 | `fgoff` | 无描边（关键：**不描边**） |
| 悬停 | `hover` | `fgon` | 120ms 过渡；600ms 后出 tooltip |
| 展开 | `accent @16%` | `accent` | 面板开着时一直保持 |
| 按下 | `accent @26%` | `accent` | 无位移、无缩放 |
| 禁用 | 透明 | `fgoff @0.4` | tooltip 说明原因，光标 `Default` |

展开态**不做**实心强调色圆底。实心块在深色顶栏上重量太大，会把视线从地址栏抢走。

### 4.3 触发入口（同一动作，四条路径）

1. **点击 chip** —— 主入口。
2. **`Alt+A`** —— 全局快捷键，与 Chrome 的 `Alt+G` 同构。
   ⚠️ 实现坑：WebView2 持有焦点时，Form 的 `KeyDown` 收不到按键。
   必须用 `CoreWebView2.AcceleratorKeyPressed`（或 `RegisterHotKey`）拦截，不能用 `KeyPreview`。
3. **地址栏前缀 `?`** —— 输入 `?这页讲了什么` 回车：打开面板，把 `这页讲了什么` 灌进输入框并直接发送。
   （不带前缀时仍然是"网址/搜索"语义，行为不变。）
4. **面板内 `✕` / `Esc`** —— 关闭，焦点回网页，不回地址栏。

### 4.4 反馈时序

| 时刻 | 发生什么 |
| --- | --- |
| 0ms | chip 立刻切到展开态；点击时**不做**缩放/回弹 |
| 0ms | 内容区**一次性**让位（`set_right_inset`），不做逐帧宽度动画 ★ |
| 0–140ms | 面板自身 `opacity 0→1` + `translateX(14px→0)`，`cubic-bezier(.2,.8,.2,1)` |
| ~70ms | 焦点落进 composer（`document.getElementById('input').focus()`） |
| 关闭 | 内容区一次性回收；chip 回落默认态；焦点交回网页 |

★ STANDARD §4 红线：不要为了"丝滑"去逐帧改内容区宽度 —— 那会让几百张卡片重新折行、封面重绘。
"高级"来自**面板这一层的位移**，不来自内容区的连续变形。

### 4.5 上下文可信度

面板打开后，用户第一眼要能确认"它看得到这一页"：

- 面板顶部已有 `当前网页 · 标题`，保留；
- composer 占位文案 `问问这个页面…`，保留；
- chip 的 tooltip 写 `AI 助手 · 对当前页提问 (Alt+A)`，不要只写 `AI`。

### 4.6 失效态（修掉现在的"假状态"）

现状 bug：在**信息流 / 悬浮窗**标签上点那颗 AI 钮，按钮会变亮，但面板永远不出现
（`shell_ai.layout()` 里 `tab_ok=False` 直接返回）。这是"说谎的控件"，比没有按钮更糟。

- 信息流 / 悬浮窗标签：chip 进入**禁用态**，tooltip 写 `信息流页请在右栏对话`；
- 或者在信息流页把 chip 改成"聚焦右栏对话"的动作（P2 可选，语义一致）；
- **无论哪种，都不许出现"高亮了但没反应"。**

### 4.7 不做的事

- 不做 `AI` 文字按钮；不做圆环描边；不做两套入口并存（chip + 右侧独立钮）。
- 不做弹跳、缩放、延迟 300ms 以上的悬停动画（用户会以为卡了）。
- 不在顶栏加 AI 提示条 / 气泡 / 红点。

## 6. 验收

```bat
python _shot_chrome.py        :: 出 chrome_{dark,light,hover,narrow,search}.png 肉眼比对
python test_shell.py          :: 顶栏结构 1~8
python app_window.py --e2e-chrome   :: 断言「标签条末行 == 导航栏首行 == 工具栏底色」
python -m py_compile shell_navbar.py shell_ai.py app_window.py
node --check web/panel.js
```

建议新增三条断言（写进 `test_shell.py`）：

1. **accent 同源**：改 `float_ball_accent` 后，chip 展开态底色 = 新 accent 的 16% 混色；
2. **命中区**：胶囊右端 4px 内点击不落到 TextBox，而是触发面板开合；
3. **禁用诚实**：信息流标签上点击 chip，`is_open()` 不变化且 chip 不进入展开态。

## 7. 红线

1. 不给原生 TextBox 加圆角/描边（会把胶囊圆角切方）。
2. 不为动效逐帧改内容区宽度。
3. 不引入第二个强调色。
4. 不用字体符号当图标。
5. 不用阴影/发光/渐变表达层次。
6. 不让控件"高亮了但什么都不发生"。
